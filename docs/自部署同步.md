# Windows + Android 自部署同步

新增原生 Windows 客户端和只负责同步的 Docker 服务。手机、电脑各自保留本地数据库，断网仍可记录。服务只需一个容器和一个持久化数据卷，不需要 MySQL、Redis 或第三方账户。

## 第一版范围

| 功能 | Windows | Android / 同步 |
|---|---|---|
| 新建、编辑、搜索文字 | 支持，输入后 600ms 自动保存 | 支持 |
| 标题、正文、Markdown 原文、正文中的 #标签 | 支持 | 双向同步，手机重建标签索引 |
| 收藏、回收站、恢复 | 支持 | 双向同步 |
| 自动同步 | 应用打开时每 60 秒 | 应用在前台时每 60 秒，编辑页面暂停接收 |
| 图片、附件、独立评论、提醒、位置、标签的自定义属性 | 暂不支持 | 保留手机本地功能，暂不上传 |
| Markdown 渲染、日历、后台常驻 | 暂不提供 | 原手机功能保留 |

文字中的本地图片路径在电脑上可能不可用。此功能是文字同步，不是包含附件的整库备份。WebDAV 备份仍可使用；不要反复导入同一份旧备份，以免生成重复记录。

## 1. 部署 Docker

将 `sync-server` 整个目录复制到服务器，进入该目录：

```sh
cp .env.example .env
```

在 `.env` 中填入自己生成的随机访问密钥，至少 32 个 ASCII 字符且不含空格。可以用 `openssl rand -hex 32` 生成。不要使用示例值，也不要把 `.env` 提交到 Git。

```dotenv
SYNC_TOKEN=这里替换为你自己的随机密钥
SYNC_PORT=8787
SYNC_BIND=0.0.0.0
```

准备同目录数据文件夹并启动（Linux，数据目录属于容器 UID 10001）：

```sh
mkdir -p data
sudo chown 10001:10001 data
docker compose up -d --build
docker compose ps
```

局域网地址示例：`http://192.168.1.100:8787`。手机和电脑都填写服务器的实际地址，手机上的 `localhost` 指的是手机自身。

公网请使用 Caddy/Nginx 等反向代理配置 HTTPS，客户端填写 `https://memo.example.com`。服务自身提供 HTTP，不处理 TLS。反向代理应允许 8 MiB 请求体、至少 60 秒超时。密钥相当于整个笔记库的访问权。这是**单人多设备**方案，一个实例对应一个笔记库。

反向代理运行在宿主机时，可将 `SYNC_BIND` 改为 `127.0.0.1`，避免直接暴露 HTTP。容器中的反向代理应通过共享 Docker 网络访问。健康检查地址为 `/health`；数据接口都要求密钥。

## 2. Windows

双击 `IdeaMemo.exe`，不需要 Python。支持 Windows x64。选择「同步设置」，填写服务地址和密钥，点击「保存并同步」。可开启自动同步，也可点击「立即同步」。

- 新建：「＋ 新建记录」或 `Ctrl+N`。
- 保存：输入后自动保存，也可按 `Ctrl+S`。
- 搜索：左侧搜索框支持标题、正文及 `#标签`。
- 删除与恢复：记录先移到回收站，勾选「显示回收站」后可恢复。
- 同步期间编辑区暂时锁定，避免覆盖未保存输入。网络失败后解锁，本地记录保留。
- 本地数据：`%LOCALAPPDATA%\IdeaMemoDesktop\notes.sqlite3`，同步设置也在其中。复制 exe 不会搬迁笔记。

当前 exe 未进行商业代码签名。若 Windows 提示发布者未知，请核对文件来源，无需关闭系统安全防护。

## 3. Android

在「数据管理 → 自部署云同步 · 设置」中填写与电脑相同的地址和密钥。首次同步上传现有顶层文字笔记，并合并服务上已有记录。

debug 测试版包名为 `com.ldlywt.note.clouddev`，与原版并存，数据各自独立。先从旧应用导出 HTML ZIP，再在测试版的数据管理中导入一次，然后开启云同步。不要卸载旧应用来解决签名不同的问题。

发布可覆盖原安装的正式版，必须使用原安装包对应的签名密钥并更新版本号，仓库不包含作者私钥。正式构建仍可在本地 `local.properties` 配置 `key.file`、`keyAlias`、`keyPassword`、`storePassword`。请保管好自己的长期签名。

## 同步规则

1. 每条记录有独立 UUID，手机自增数据库 ID 不会与电脑互相覆盖。
2. 使用服务端版本号判断冲突，不按设备时钟决定覆盖顺序。
3. 两端离线修改同一记录：保留先收到的版本，后收到的不同内容另存为「同步冲突副本」。下次同步后两端都能看到，请手动整理。
4. 永久删除保留服务端删除标记；旧设备上线不会无故复活记录。如果旧设备有新的编辑，则保留为冲突副本。
5. 永久删除与另一端新编辑冲突时，优先保留新编辑，并显示冲突提示。回收站状态也是记录的一部分。
6. 提交成功但响应丢失时，重试不会重复应用同一修改或无限生成冲突副本。
7. 同步期间新的本地修改会保留，远端列表缺少某条记录不会被理解为删除它。
8. 客户端绑定服务的数据卷身份。换域名并保留原数据卷可以继续同步；意外丢失或换成新数据卷会停止同步，请恢复原卷。

服务采用全量返回、仅上传变化的简单协议，适合个人文字笔记。单次最多 5000 条修改、8 MiB，客户端响应最多 64 MiB。大规模笔记库需要先扩展分页/增量协议，不能通过重试突破上限。重试凭据和删除标记会持久保存，需要定期检查磁盘容量。

## 备份与升级

数据保存在服务目录下的 `data` 文件夹，通过 bind mount 挂入容器。升级运行 `docker compose up -d --build`。不要删除 `data`，其中同时保存笔记库、删除标记和服务身份。

冷备份：先 `docker compose stop sync`，备份整个 `data` 文件夹和 `.env`，再 `docker compose start sync`。恢复时也先停止服务并恢复整个文件夹，包括存在的 SQLite WAL/SHM 文件；保持 UID/GID 10001 的访问权限。只复制运行中的单个 `.sqlite3` 文件可能遗漏最新数据。

Windows 备份：关闭客户端后，备份 `%LOCALAPPDATA%\IdeaMemoDesktop` 整个目录。手机重要资料继续定期使用原有导出备份功能。

## 源码构建与测试

Windows：Python 3.13 或 3.14，含 Tk。

```powershell
python -m pip install -r desktop/requirements-build.txt
./desktop/build.ps1
```

输出 `desktop/dist/IdeaMemo.exe`。开发运行：`python desktop/main.py`。

Android：JDK 17、Android SDK 36。Gradle 会按需安装 Build Tools 34.0.0。配置 `ANDROID_HOME` 或本地 `local.properties` 中的 `sdk.dir`：

```sh
./gradlew :app:assembleDebug
```

Windows 使用 `gradlew.bat :app:assembleDebug`，无需作者签名。机器专用代理请配置在用户的 Gradle 配置中。

`.github/workflows/cloud-build.yml` 在推送后或手动运行时生成 exe、测试 APK，并构建/检查 Docker 服务。它不自动发布商店应用或 Docker 镜像。

```sh
python -m unittest discover -s tests -v
```

Tk 测试需要桌面会话；仅测试同步可运行 `python -m unittest discover -s tests -p test_sync.py -v`。测试使用临时数据和本机随机端口，不访问个人笔记。
